# Rubric: is this reproduction package ready to post?

All dates and versions are measured against the bundle's capture date in eval mode, and against today in live mode.

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| env-recorded | **Live (`gh` / draft):**<br>`gh issue view {issue} -R {owner}/{repo} --json body`<br>Draft repro report "Environment" section<br><br>**Eval (bundle):**<br>"Environment" block in Candidate repro report read against the Issue description | The report records the operating system (with architecture when relevant), tool/app version, and toolchain used. If the tested version differs from the issue's reported version, the delta must be stated. Fails if environment details are absent or omit an essential platform target specified by the issue. | required |
| steps-followable | **Live (`gh` / draft):**<br>Draft repro report "Steps to reproduce" and test commands<br><br>**Eval (bundle):**<br>"Steps to reproduce" section in Candidate repro report | Setup and reproduction commands are sequential, self-contained, and executable from a clean starting state by a stranger. Fails if the steps rely on private monorepos, unshared local configs, secret files, or skip the trigger action that induces the defect. | required |
| behavior-matches | **Live (`gh` / draft):**<br>`gh issue view {issue} -R {owner}/{repo} --json title,body`<br>Output excerpts and logs in the draft repro report<br><br>**Eval (bundle):**<br>Output/log excerpts in Candidate repro report read against the Issue description | The observed behavior matches the specific bug reported in the issue (same error message, panic, crash signal, or incorrect output). FAILS if the observed behavior is an adjacent symptom, a generic syntax or argument validation error caused by modified/mistyped input (e.g. typing `:` instead of `=`), or a failure on an unacknowledged old version. An honest, evidenced cannot-reproduce on the exact trigger steps passes. | required |
| honest-evidence | **Live (`gh` / draft):**<br>Embedded output logs, terminal traces, and screenshots in draft report<br><br>**Eval (bundle):**<br>Embedded artifacts and expected/actual sections in Candidate repro report | The report's claims are directly backed by concrete, visible artifacts (terminal transcripts, exit codes, logs, or UI captures). Both expected and actual outcomes are stated. If cannot-reproduce, it is stated honestly with what was attempted, what differed, and the resulting artifact. FAILS if: (1) claims reproduction or asserts root cause with zero supporting artifacts, (2) the artifact shows normal operation while claiming failure, or (3) actual and expected are stated backwards. | required |
| claim-and-policy | **Live (`gh` / draft):**<br>`gh api repos/{owner}/{repo}/community/profile --jq '.files.contributing.html_url'`<br>`gh api repos/{owner}/{repo}/contents/CONTRIBUTING.md`<br>`gh api repos/{owner}/{repo}/contents/AI_POLICY.md`<br>Draft claim comment<br><br>**Eval (bundle):**<br>Candidate claim comment read against "contribution policy" under Repo facts | (1) The claim comment states a specific, modest intent to work on the issue without interchangeable boilerplate, +1s, or unrealistic guarantees (e.g. "guaranteed 2-day fix"), AND (2) complies with the repository's stated contribution policy (including explicit disclosure of AI assistance where required by the repository). Fails if AI disclosure is omitted on a repository that mandates it. | required |
| control-artifact | **Live (`gh` / draft):**<br>Side-by-side terminal logs or control run outputs in draft report<br><br>**Eval (bundle):**<br>Artifact sections showing working vs failing comparisons in Candidate repro report | The report includes a formatted verbatim log and/or a control run (demonstrating expected behavior under normal input alongside failing behavior under trigger input) that cleanly isolates the defect. | preferred |

## Verdict rule

READY (accept) only if every required check passes. Preferred checks never change the verdict and serve only to rank package quality. Any FAIL or UNCLEAR on any required check results in HOLD (reject): a reproduction package that cannot be independently verified or whose proof is unevidenced must not be posted upstream.
