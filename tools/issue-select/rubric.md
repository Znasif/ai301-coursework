# Rubric: is this a good first issue?

All dates are measured against the bundle's capture date in eval mode, and against today in live mode. Maintainers are users with OWNER, MEMBER, or COLLABORATOR badges.

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| maintainer-alive | **Live (`gh`):**<br>`gh api repos/{owner}/{repo}/commits?per_page=5 --jq '.[].commit.author.date'`<br>`gh issue list -R {owner}/{repo} --state all -L 5 --json number,comments,updatedAt`<br><br>**Eval (bundle):**<br>"maintainer first-response sample" and "last 5 default-branch commits" under Repo facts | Passes if EITHER (a) at least one of the sampled issues got its first OWNER, MEMBER, or COLLABORATOR comment within 30 days, OR (b) at least one of the last 5 default-branch commits is dated within 30 days of the capture date and was authored by a human (an author name that does not end in "[bot]"). "No maintainer comment in thread" counts as no response for that issue. Fails only if neither (a) nor (b) holds. | required |
| repo-alive | **Live (`gh`):**<br>`gh repo view {owner}/{repo} --json isArchived,latestRelease,pushedAt`<br><br>**Eval (bundle):**<br>"archived:", "latest release", and "last push to any branch" under Repo facts | The repo is not archived, AND either (a) the latest release is dated within 120 days (4 months) of the capture date, or (b) the repo has no releases at all and its last push to any branch is within 30 days of the capture date. A repo whose latest release is older than 120 days fails, even if it has recent pushes. | required |
| bounded-scope | **Live (`gh`):**<br>`gh issue view {issue} -R {owner}/{repo} --json title,body,comments,createdAt`<br>`gh pr list -R {owner}/{repo} --state all --search "fixes #{issue}"`<br><br>**Eval (bundle):**<br>Issue body, comment thread (author_association), "linked PRs" under Repo facts, and issue open date | Fails if ANY of these is true: (1) the issue itself says it is an umbrella, tracking or meta issue, or explicitly asks for the work to be split into separate PRs or sub-issues (several related edits that together deliver one stated outcome count as one bounded piece of work, not an umbrella); (2) the thread shows the design is still being debated and no OWNER, MEMBER, or COLLABORATOR has settled it; (3) an OWNER, MEMBER, or COLLABORATOR says the fix requires changes to core internals; (4) the issue is a usage or support question rather than a requested change; (5) the issue was opened more than 365 days before the capture date AND has two or more closed, unmerged PRs (abandoned attempts); (6) it is a new feature proposal from a non-maintainer with zero maintainer comments, no maintainer approval, and no maintainer-applied labels confirming the feature is wanted. Otherwise passes. A short body, a checklist-style body, or a bug report without reproduction steps does NOT fail this check on its own. | required |
| not-claimed | **Live (`gh`):**<br>`gh issue view {issue} -R {owner}/{repo} --json assignees,comments`<br>`gh pr list -R {owner}/{repo} --state open --search "{issue}"`<br><br>**Eval (bundle):**<br>"this issue: assignees:" and "linked PRs:" under Repo facts, plus comment thread | No one is assigned, AND there is no open PR for this issue, whether formally linked or only mentioned in the comments. Closed, unmerged PRs are abandoned attempts, not claims. "I'll take this" comments with no assignee and no open PR do not count as a claim (in Path Review, ignore peer student claims per house rule). | required |
| ai-policy | **Live (`gh`):**<br>`gh api repos/{owner}/{repo}/community/profile --jq '.files.contributing.html_url'`<br>`gh api repos/{owner}/{repo}/contents/CONTRIBUTING.md`<br>`gh api repos/{owner}/{repo}/contents/AI_POLICY.md`<br><br>**Eval (bundle):**<br>"contribution policy" line under Repo facts | The policy does not ban AI-generated or AI-assisted contributions. Conditions such as disclosing AI use, reviewing and understanding AI output, or testing changes are terms to follow and pass. A repo that states no policy passes. | required |
| stars | **Live (`gh`):**<br>`gh repo view {owner}/{repo} --json stargazerCount`<br><br>**Eval (bundle):**<br>Star count on the repo line under Repo facts | Repo has 100 or more stars | preferred |

## Verdict rule

Accept if all required checks pass. Every required check is mandatory, so a single fail on any required check rejects the issue. Preferred checks never change the accept/reject verdict; among accepted issues, rank higher the ones with more preferred checks passing. Unclear on any required check counts as fail: if the evidence a check needs is genuinely absent, the issue is rejected, because a first issue I cannot verify is not one I should take.
