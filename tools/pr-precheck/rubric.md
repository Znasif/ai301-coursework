# Rubric: is this pull request ready to submit?

All dates and versions are measured against the bundle's capture date in eval mode, and against today in live mode. Maintainers are users with OWNER, MEMBER, or COLLABORATOR badges. "The plan" means the posted plan together with its recorded deviation notes. Where each piece of evidence lives, in live and eval mode, is in `references/evidence-guide.md`.

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan-fidelity | Diff and description read against the plan.<br>`evidence-guide.md` → Plan fidelity | Passes if every hunk in the diff implements the plan or a recorded deviation, every item the plan promises is in the diff or disclosed as missing in both the plan and the description, and no claim the description makes about the change is contradicted by the diff. FAILS if the diff adds an unplanned feature, option, or rewrite, or edits a file the plan never names, even when the description says the PR does nothing beyond the plan. Grade the diff, not the description. | required |
| decisive-evidence | Test evidence read against the plan's test plan and repro.<br>`evidence-guide.md` → Test evidence | Passes if the evidence re-runs the reproduced failure against the change, on the path the change touches, shows the output after the fix, shows or quotes the output before, and the result matches the plan's expected outcome. Every distinct failure the repro pinned down must be re-run. FAILS if the evidence only claims testing with no output shown, runs only a control or a different path, or never re-runs one of the reproduced failures. | required |
| clean-diff | Diff hunks and commit list.<br>`evidence-guide.md` → Diff quality | Passes if every changed line in the diff, as `git diff` prints it, is part of the change. FAILS if the diff leaves in debug prints, commented-out code, or dead code; churns formatting or imports on lines the change does not otherwise touch; moves unchanged code to a different place in the file or re-indents it, unless the plan calls for the move (unchanged lines that repeat inside a block rewritten in the same place are not a move); or makes unrelated drive-by edits. Commit messages alone never fail this check. | required |
| standards-met | Title, description, and diff read against the repo's PR template, contributing guide, and AI policy.<br>`evidence-guide.md` → Standards and comms | Passes if every section, checklist item, and file the PR template or contributing guide requires is actually present, not left as a placeholder or only claimed (for example, a required changelog entry must be in the diff), and the description discloses the AI tool and the extent of its use when the stated AI policy requires that for pull requests. Treat every package as AI-assisted work. FAILS if a required item is missing, a placeholder, or claimed in the description but absent from the diff, or a required AI disclosure is missing. Asks the repo does not state are not required. | required |
| engages-thread | Description read against maintainer comments in the thread.<br>`evidence-guide.md` → Standards and comms | Passes if the description engages any maintainer question or direction in the thread that bears on the change. | preferred |
| repo-checks-shown | Test evidence read against the repo's own test command.<br>`evidence-guide.md` → Test evidence | Passes if the result of the repo's own test or check command is shown, not just claimed. | preferred |

## Verdict rule

READY (accept) only if every required check passes (`plan-fidelity`, `decisive-evidence`, `clean-diff`, `standards-met`). Preferred checks (`engages-thread`, `repo-checks-shown`) never change the verdict and are reported for the author. Any FAIL or UNCLEAR on any required check results in HOLD (reject): a PR that drifts from its plan, does not show its fix working, buries the fix in noise, or skips the repo's stated requirements must not be submitted.
